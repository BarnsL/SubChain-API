Overview

SubChain puts one OpenAI-compatible endpoint in front of an ordered chain of subscription providers. Your apps point at this server with a single fixed key; it holds the real credentials and walks the chain until something answers.

HTTP error legend

Provider state means configured, not live-tested. Cooling applies to one route so another subscription or key can answer. A subscription can also be skipped before any error when its measured usage is over the configured threshold.

400 / 422 · request rejected
The provider says the request itself is invalid or unsupported. SubChain stops instead of spending every route. An Anthropic 400 that reports the account is out of usage is the documented exception: it marks that subscription exhausted, cools it for ten minutes, and the chain continues.
401 / 403 · credential or session rejected
The API key was refused, or a subscription session expired and its OAuth token no longer authenticates. That route cools and the next one is tried; re-sign in or replace the credential on Providers.
404 · endpoint or model missing
The provider does not recognise the configured endpoint or model. The route cools while the chain continues; update the matching provider or Chain entry.
408 / network · timeout or unreachable
The provider did not answer inside the configured request timeout, or the connection failed. That route cools and SubChain advances to the next one.
409 · subscription not signed in
A managed transport refused the handoff because its CLI is not signed in, or the account behind it carries no active subscription. The route cools; complete sign-in on Providers.
429 · rate limited or window exhausted
The subscription or key is being limited. SubChain honours Retry-After when supplied, otherwise the configured cooldown. When the response names a quota family, the whole window (for example the five-hour or weekly allowance) is marked exhausted and skipped until it resets. An Anthropic 429 caused by a wrong system block cools for ten minutes instead.
5xx · provider or transport failure
The provider reported a server-side error, or a managed transport failed its handoff and returned 502. SubChain cools that route and continues down the chain.

Local API keys

Create up to ten independent keys for your local apps. Each key can reach one provider or one ordered chain, while provider credentials remain local to this machine.

Keys are shown only on this local dashboard. Rotating one never changes another key.

Log policy
What the journal is allowed to keep.

            

              By default SubChain writes metadata only: which local key called, which provider
              answered, how long it took. Everything below turns some part of the actual traffic
              into a stored record on this machine. Each one is off until you turn it on, and the
              Logs page always states the policy currently in force.
